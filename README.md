# Iron Helm 桌游数字化开发资料整理

以下是根据搜索材料整理的系统性资料，涵盖Iron Helm桌游的核心规则、组件清单、世界观设定等八个关键维度，为电子游戏开发提供完整参考。


## 一、游戏核心规则文档

### 1.1 游戏概述

Iron Helm是一款**单人地牢爬行类桌游**，由Jason Glover设计，Grey Gnome Games出版。玩家扮演一位寻求最后一次大收获后退休的英雄，深入Blackened Mountains的地牢展开冒险。

**基础信息**：
- 玩家人数：1人（纯单人游戏）
- 游戏时长：30-60分钟
- 推荐年龄：12岁以上

### 1.2 核心机制

**抽二选一机制（Draw Two, Pick One）**：
- 玩家从地牢牌堆抽取两张牌
- 翻开其中一张查看内容
- 决定：①解决已翻开的卡牌，或②冒险选择未知的另一张

这一机制是整个游戏决策系统的核心，创造了“已知风险 vs 未知可能”的紧张感。

### 1.3 回合流程

游戏流程结构如下：

**阶段一：准备阶段**
- 玩家初始获得一定数量的金币
- 使用金币在城镇购买装备（武器、防具、道具）

**阶段二：地牢探索（核心循环）**
- 每个地牢层级重复以下步骤：
  1. 抽取两张地牢卡牌
  2. 选择一张解决
  3. 遭遇内容：敌人、宝藏、剧情卡牌、陷阱等
  4. 管理生命值和能量值
  5. 处理状态效果（中毒、迷路等）

**阶段三：胜利条件**
- 通过解决特定数量的剧情卡牌来**解锁地牢Boss**
- 击败Boss获得胜利
- 根据多项成就计算最终分数，决定退休生活质量

### 1.4 角色系统

**初始角色**（基础游戏包含4个角色）：
- 每个角色拥有独特的**技能熟练度**（角色卡右下角标注）
- 熟练度类型示例：Brawn（力量）、Agility（敏捷）等

**技能学习机制**：
- 击败敌人后，保留敌人卡牌作为经验值
- 累积3张敌人卡牌 → 可学习1个与熟练度匹配的技能
- 学习熟练度外的技能 → 需要5张敌人卡牌

### 1.5 战斗机制

**基础战斗流程**：
- 使用装备的主手/副手武器进行攻击
- 消耗能量值执行某些行动
- 可选择投掷斧头（强力一击但永久失去该武器）

**骰子机制**：
- 使用2个12面骰和3个6面骰
- 战斗中可使用**祝福代币**重掷所有骰子（使用前不查看代币正面）

### 1.6 状态与资源系统

**核心资源**：
| 资源类型 | 功能              | 基础数量   |
| -------- | ----------------- | ---------- |
| 生命值   | 归零即游戏结束    | 视角色而定 |
| 能量值   | 执行行动消耗      | 视角色而定 |
| 金币     | 购买装备          | 初始若干   |
| 口粮     | 休息时恢复能量    | 可变       |
| 祝福代币 | 战斗重掷/终局得分 | 面朝下持有 |

**中毒机制**：
- 通过多种方式获得中毒标记
- 中毒标记数量 ≥ 当前生命值时，**立即死亡**，游戏结束

**状态效果**：
- 扩展包引入**Afflictions（苦难）**：无法进食、中毒等级达到3、特定敌人造成

### 1.7 装备系统

**装备槽位**（详见附录规则）：
| 槽位代码 | 部位 | 限制          |
| -------- | ---- | ------------- |
| PH       | 主手 | 仅1件         |
| OH       | 副手 | 仅1件         |
| 2H       | 双手 | 占用主手+副手 |
| HD       | 头部 | 仅1件         |
| BD       | 身体 | 仅1件         |
| AS       | 饰品 | 无限制        |

**负重限制**：
- 装备总重量不能超过负重上限
- 超出时可丢弃现有装备以腾出空间

### 1.8 扩展系统（Iron Chest扩展）

大型扩展Iron Chest新增以下系统：

| 新系统                    | 功能说明                                                             |
| ------------------------- | -------------------------------------------------------------------- |
| **Artifacts（神器）**     | 比战利品更强大的装备；用祝福代币换取（首次1个，第二次2个，依次递增） |
| **Environments（环境）**  | 每层地牢开始时抽取；改变该层规则（增强敌人、提供支线任务等）         |
| **Henchmen（随从）**      | 在Inn招募；提供被动加成；用d6骰子追踪士气；士气归零则离开            |
| **Afflictions（苦难）**   | 新增负面状态系统                                                     |
| **Mini Bosses（小Boss）** | 剧情卡牌变体；击败后获得4个眼睛标记，加速推进主线                    |

**随从系统详解**：
- 同时只能拥有1名随从
- 不同随从有不同士气损失条件（被伏击/对战亡灵/承受重击）
- 可用金币提升士气

## 三、游戏背景故事与世界观设定

### 3.1 核心叙事框架

**开篇设定**：
> “你布满老茧的手紧握剑柄。鲜血与汗水混合，从额头滴落，刺痛着你的眼睛。沉重的脚步声震撼着大地，你试图稳住 aching的双脚。你转身面对敌人，低声自语：‘我太老了，干不了这个……’”

**核心动机**：英雄寻求在Blackened Mountains地牢中完成**最后一次大收获**，之后光荣退休。

### 3.2 世界观元素

**The Lonely Troll（孤独巨魔酒馆）**：
- 文明最远端的最后一家酒馆
- 英雄与恶棍的聚集地
- 可在此雇佣随从、购买装备、在冒险间隙休息

**The Spire of Zogar（佐加之塔）**：
- 4级难度冒险（最高等级）
- 需完成基础冒险→2级冒险→3级冒险后方可挑战
- Zogar是Grey Gnome Games宇宙中最强大的反派，此前从未在游戏中正式登场

### 3.3 叙事风格

- **基调**：黑暗英雄主义 + 黑色幽默
- **视角**：第一人称沉浸式体验
- **结局**：根据得分决定退休生活质量，形成叙事闭环


## 四、游戏平衡数据

### 4.1 资源管理数据

| 资源类型 | 初始值         | 获取方式           | 消耗方式                    |
| -------- | -------------- | ------------------ | --------------------------- |
| 金币     | 若干（视角色） | 击败敌人、发现宝藏 | 购买装备、雇佣随从          |
| 口粮     | 可变           | 战利品、购买       | 休息恢复能量（1口粮=1能量） |
| 祝福代币 | 0              | 特定事件           | 重掷骰子、终局得分          |

**口粮使用优化**：
- 普通口粮：直接使用获得1能量
- 营地卡牌烹饪：获得3能量（更高效）
- 优质口粮（战利品获得）：直接使用2能量，烹饪仍为3能量

### 4.2 战斗平衡数据

**斧头投掷机制**：
- 不消耗能量
- 造成强力一击
- **代价**：斧头永久失去，必须从游戏中移除

**药水使用规则**：
- 非攻击性药水：任意时机使用
- 攻击性药水（冰刃、圣水、火花炸弹）：战斗中替代武器攻击
- **限制**：不能同时使用武器和攻击性药水，二选一

### 4.3 技能学习成本

| 技能类型     | 所需敌人卡牌数 | 条件           |
| ------------ | -------------- | -------------- |
| 熟练度内技能 | 3张            | 角色熟练度匹配 |
| 熟练度外技能 | 5张            | 无限制         |

**示例**：Mike扮演Molician（擅长Brawn技能），想学习Archery（Agility技能）。他击败了4个敌人，仍需再击败1个（共5个）才能学习该技能。

### 4.4 扩展平衡调整

**神器获取成本**（递增式）：
| 第N次换取 | 祝福代币成本 |
| --------- | ------------ |
| 第1次     | 1个          |
| 第2次     | 2个          |
| 第3次     | 3个          |

**设计意图**：获取超过2个神器极其困难，平衡强力装备的获取频率。

### 4.5 胜利条件与得分机制

**主线推进**：
- 通过解决剧情卡牌获得**眼睛标记**
- 达到特定眼睛标记数量 → 解锁Boss

**Mini Boss机制**（Beasts & Burdens扩展）：
- 击败Mini Boss获得4个眼睛标记
- 快速推进主线进度

**终局得分**：
- 基于多项成就计算
- 决定角色退休生活的品质


## 五、玩家交互机制

### 5.1 核心定位

Iron Helm是**纯单人游戏**，没有多人交互机制。

### 5.2 玩家与系统的交互方式

| 交互类型     | 机制说明                                 |
| ------------ | ---------------------------------------- |
| 决策交互     | 抽二选一机制制造风险决策                 |
| 资源管理     | 生命/能量/负重三线管理                   |
| 装备配置     | 槽位限制下的策略搭配                     |
| 技能成长     | 击败敌人→累积经验→学习技能               |
| 扩展内容选择 | 玩家自主决定添加哪些扩展包（难度自定义） |

### 5.3 数字化改造建议

转换为电子游戏时，可考虑：
1. **保留单人核心体验**（不建议强行添加多人模式）
2. 添加**异步排行榜**功能（分数对比）
3. 添加**每日地牢挑战**模式
4. 考虑**roguelite永久升级**系统

## 七、目标玩家群体分析

### 7.1 桌游现有玩家特征

根据产品页面数据：
- **平台评分**：97条评价（平均4.5星以上）
- **核心标签**：硬核玩家、喜欢风险决策、喜欢地下城探险
- **游戏方式偏好**：单人沉浸式体验

**玩家画像**：
| 维度     | 特征                                  |
| -------- | ------------------------------------- |
| 年龄     | 25-45岁为主                           |
| 游戏经验 | 中重度桌游玩家                        |
| 时间预算 | 30-60分钟单次游戏                     |
| 购买动机 | 寻求高质量单人体验、喜欢rougelite元素 |
| 痛点     | 设置/收纳时间长、缺少变化性           |

### 7.2 数字化优势转化

| 桌游痛点     | 数字化解决方案           |
| ------------ | ------------------------ |
| 设置时间长   | 一键开局，自动规则执行   |
| 牌堆管理繁琐 | 自动洗牌、分牌、归档     |
| 标记管理麻烦 | 自动追踪生命/能量/中毒等 |
| 缺少变化性   | 程序生成地牢，无限重玩性 |
| 规则记忆负担 | 内置规则提示，自动判定   |

### 7.3 电子游戏潜在玩家需求

**目标平台偏好**：
- 优先级1：PC（Steam）- 重度策略玩家聚集
- 优先级2：Nintendo Switch - 便携单人体验
- 优先级3：iOS/Android - 休闲向

**核心需求**：
1. 快速开始（单局30分钟内）
2. 自动保存/中途退出功能
3. 数据统计与成就系统
4. 每日挑战模式
5. 云存档同步


## 八、类似电子桌游成功案例分析

### 8.1 可参考竞品（单人地牢爬行类）

以下是在Steam上成功的单人卡牌地牢爬行游戏，可作为设计参考：

**Slay the Spire（杀戮尖塔）**
- 核心机制：卡牌构建 + 地牢爬行
- 成功要素：深度策略性、高重玩性、简洁UI
- 参考价值：卡牌战斗系统的数值平衡设计

**Darkest Dungeon（暗黑地牢）**
- 核心机制：队伍管理 + 永久死亡 + 压力系统
- 成功要素：氛围营造、资源管理深度
- 参考价值：状态系统设计、风险回报平衡

**Monster Train（怪物火车）**
- 核心机制：牌组构建 + 塔防
- 成功要素：快节奏、多种族组合
- 参考价值：扩展系统的模块化设计

### 8.2 传统桌游电子化成功案例

**Tabletop Simulator**：
- 定位：物理模拟平台
- 成功点：保留桌游触感
- 对Iron Helm参考价值有限（Iron Helm更适合规则自动化）

**Gloomhaven数字版**：
- 核心：重度桌游的完全自动化
- 成功要素：忠实还原 + 自动化管理 + 单人战役
- **直接参考价值高**：同为单人地牢爬行，可借鉴UI/UX设计

### 8.3 数字化经验教训总结

**应避免的陷阱**：
1. 过度简化核心机制（失去策略深度）
2. 破坏单人沉浸体验（强行添加多人）
3. 忽视规则自动化（保留桌游的繁琐管理）
4. UI过于复杂（信息过载）

**应采纳的设计原则**：
1. **忠实核心，优化外围**：保留抽二选一核心，自动化标记追踪
2. **渐进式教程**：分层介绍机制，避免信息轰炸
3. **视觉反馈强化**：卡牌效果动画、资源变化动效
4. **速度控制选项**：动画速度调节、跳过动画等
5. **数据可视化**：战斗胜率预测、资源消耗预览
